# Proposed ADR: A native edition is quoted and receipted by the server

Status: proposed source design. Extends the display-only contract in ADR-0023 and ADR-0024; does not enable purchase or approve any product terms.

## Decision

- **Selection and quote.** A verified buyer submits an explicit parent and native variant ID, not the label, price, inventory, shipping amount or benefits. Reuse the approved native parent/option projection, native SKU price and stock, and approved publication. A server-owned operational terms record must explicitly approve that SKU for this buyer and sale window, supply the shipping fee and references to offer, disclosure/consent, fulfillment and benefit rules. An absent or inconsistent input produces no quote. A quote is neither a reservation, a bearer credential nor payment permission. No price, fulfillment, or premium defaults.
- **Bind and reserve.** One native cart line stores the parent and chosen variant relation. Bind it to the canonical member, explicit release, one-unit current allowance and quote under the cart/attempt lock; re-read the quote and require explicit reconfirmation for changed charge, edition or terms before initiating payment. Keep the existing shared allowance keyed by buyer and parent release, not multiplied by variant. Reserve selected SKU stock under an ordered SKU + release lock; use event-capacity reservation only for explicitly mapped event benefits. Save one immutable versioned attempt snapshot and hash, including SKU, receipt label, quantity, exact charge/shipping and fulfillment/benefit decision. Freeze the approved versions/content needed for later fulfillment, consent and benefits. Retry the same attempt using the saved snapshot, never a fresh quote; reject SKU, owner, or cart rebind.
- **Finalize and receipt.** Keep the installed Payload ecommerce `finalizeOrder` transaction seam and canonical PortOne evidence/risk checks. Validate exact provider charge and owner, snapshot/hash, variant line and reservation before finalizing once. The plugin owns cart/order/transaction linkage and stock decrement; audit the included native inventory mutation under the same locks to avoid double depletion. The selected-edition receipt and approved effects read frozen facts from the saved snapshot, not mutable variant labels, current policies or the return payload. Do not let the legacy unconditional admission/membership/key hooks consume native attempts. No event or token is implied by successful payment.
- **Compatibility.** Existing carts, stored version-1 snapshots/hashes, transaction/result states, reservation keys, receipts and in-flight attempts retain their exact semantics and recovery path; do not backfill or reinterpret them. Dispatch on explicit frozen version: missing/invalid native evidence fails closed, never falls back to legacy. Keep `purchaseReady:false` and legacy isolation until a complete native prepare/reconcile/finalize path exists and is independently exercised.

## Source slices

1. Quote reader/projection: explicit identity, current authorized configured inputs, no write or consumer. The operational-terms producer does not yet exist; no positive quote in canonical runtime.
2. Versioned receipt projection: explicitly native frozen facts and same owner, legacy and in-flight formats unchanged, no new order write or UI assertion.
3. Cart/checkout attach: introduce native line/attempt/reservation persistence and reviewed settlement/finalize dispatch together. Do not enable installed plugin variant purchase globally as a shortcut. Exercise wrong owner, stale quote, concurrent last SKU, changed SKU retry, and one receipt/stock consumption after replay before activation.

Owner inputs: the approved purchasable SKU set and actual sales/fulfillment facts, per-edition benefit and event-capacity effects, and applicable consent, personalization and return rules. An unset or exploratory premium SKU stays off. These inputs do not authorize a provider call, a migration run, or rollout.
